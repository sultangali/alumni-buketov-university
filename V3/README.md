# Alumni Buketov University — V3

Рабочая web-версия и вертикальный touch kiosk на React + TypeScript. Общий Express/MongoDB API проекта, без отдельной базы V3.

## Локальный запуск

Из `V3/app`: `npm ci`, затем `npm run dev`. Порт строго **5183**, V1/V2 на других портах не затрагиваются.

- Web: http://127.0.0.1:5183/?preview=browser&page=home
- Kiosk: http://127.0.0.1:5183/?preview=kiosk&page=home
- Заявка: http://127.0.0.1:5183/u/apply

Запустите исправленный общий backend на4000 с существующей MongoDB `alumni`. Vite проксирует `/api` и `/media` на backend; браузер использует свой origin, поэтому удалённый Android не обращается к собственному localhost. `VITE_API_URL` обычно не задаётся. Полный seed **не нужен**.

## Что входит

Холодная светлая палитра, локальный Noto Sans с кириллицей и казахскими буквами, радиусы до8px. Факультеты равноправны, отсортированы по названию выбранного языка. Поиск по всем категориям, профили с реальным фото или монограммой, без искусственных достижений и placeholder-галерей. Пустые биография/наставники/ученики/медиа не выводятся. Заявки и сотрудники используют исправленную логику V2. Киоск имеет экранную KZ/RU/EN клавиатуру и idle60s с очисткой сессии.

Web при ширине <=1100px раскрывает действия через «Меню»; языки остаются видимыми. Киоск запускается явно параметром `preview=kiosk`, web не превращается в киоск при сужении окна.

## Сборка и Ubuntu24.04/Nginx

1. Пока есть интернет, установите зависимости `npm ci` в `V3/app` и `server`. Соберите `npm run build` в каждой папке. Проверенный локальный Node24; на Ubuntu используйте поддерживаемую версию Node, совместимую с Vite5 и lockfile.
2. Статика V3 находится в `V3/app/dist`: JS/CSS, логотипы и шрифты включены. CDN и запросов шрифтов в интернет нет. Скопируйте **весь dist**, не только index.html. Зависимости нужны на этапе сборки; без интернета на Ubuntu используйте заранее собранный dist.
3. Backend запускайте существующим systemd unit из `deploy`, с сохранённым `.env`/JWT_SECRET/MONGO_URI и папкой медиа. Не публикуйте `.env` и MongoDB в GitHub.
4. Пример дополнительного Nginx server block — `V3/deploy/nginx-v3.conf.example`. Он слушает8083 и не заменяет существующий сайт на80. Скорректируйте root под фактическую папку установки, затем обычные `nginx -t` и reload выполняются уже администратором сервера. Здесь deploy не выполнялся.
5. На Android откройте `http://<IP-адрес-Ubuntu>:8083/?preview=kiosk&page=home`, на ноутбуке — тот же адрес без режима kiosk. Оба устройства должны иметь доступ к серверу. Конфигурация Ethernet/IP в этой задаче не менялась.

V1/V2 можно оставить на прежних портах или создать для их dist отдельные server blocks8081/8082 с теми же `/api` и `/media` proxy. Для этих версий предпочтительнее отдельные порты/hostnames, а не подпапки `/v1`/`/v2`: текущая история и assets используют корневые пути. Все версии работают с одной базой, публикация сотрудником видна всем после обновления данных.

QR ведёт на `/u/apply` текущего сервера. При прямом Ethernet без общей сети телефон посетителя не сможет открыть этот адрес — доступно заполнение формы непосредственно на киоске.

## Данные для завтрашнего показа

GitHub переносит код, **не текущую MongoDB и не загруженные media**. Существующие15 факультетов/5 demo-выпускников/6 преподавателей/6 лауреатов/5 ветеранов находятся в общей локальной базе. Если университетский сервер ещё не содержит эти записи, их перенос требует отдельной резервной копии MongoDB и медиа; не запускайте destructive seed для восстановления. Demo-профили сохраняют указание, что они вымышленные.
