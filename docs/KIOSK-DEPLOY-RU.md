# Развёртывание отказоустойчивого киоска

Этот документ описывает установку. Сброс устройства, изменение сетевых настроек, публикация и перенос реальной базы автоматически не выполнялись.

## Для показа по прямому кабелю

1. Сохранить резервную копию MongoDB и каталога `server/uploads`, старого приложения киоска и его настроек. Перенос кода не переносит базу и фотографии. Seed не запускать.
2. Соединить Ethernet-порты сервера и киоска. Отключить остальные сетевые подключения на время изолированного показа. Назначить разные статические адреса в одной подсети, например серверу `192.168.50.1/24`, киоску `192.168.50.2/24`. Эти адреса нужно действительно установить; фотография экрана не подтверждает текущую конфигурацию сервера. При прямом соединении шлюз и DNS не требуются. Поддержку статического Ethernet проверить в прошивке Android.
3. Собрать и запустить существующий backend, сохранив его `.env`, базу и медиа. Новые параметры: `HOST=127.0.0.1`; `PUBLIC_APP_ORIGIN` пустой; `CORS_ORIGINS` пустой при едином origin сайта/API. MongoDB должна быть доступна только серверу.
4. Собрать `V3/app` и разместить весь `dist` на сервере. Пример Nginx: `V3/deploy/nginx-v3.conf.example`; он раздаёт V3 на порту `8083` и проксирует `/api` и `/media` на backend. Проверить фактический путь `root`, `nginx -t` и ответ `/api/health` прежде чем перезагружать конфигурацию.
5. В настройках приложения указать `http://192.168.50.1:8083` — только если этот адрес установлен на сервере и порт включён. Публичный адрес формы оставить пустым: QR для телефона в кабельном контуре не предлагается.
6. Перед отключением кабеля дать киоску получить каталог и фотографии. Пустая первая установка ещё не содержит университетских данных. Наличие интерфейса внутри APK не заменяет первоначальную синхронизацию каталога.
7. Провести проверку: отключить кабель, перезапустить приложение, открыть профиль, заполнить текстовую заявку. После подключения убедиться в появлении одной заявки на сервере. Повторить обрыв во время отправки.

## Что означает офлайн-режим

Приложение содержит интерфейс. Опубликованный каталог хранится отдельной проверенной копией, фотографии — в ограниченном локальном хранилище. Крупные или ещё не скачанные медиа могут быть недоступны без сервера. Следует заранее проверить конкретные профили и слайд-шоу, которые будут показаны.

Посетитель может отправить текстовую анкету без фотографии. Сообщение «сохранена на киоске» появляется после локальной записи; это не утверждение, что сервер уже получил анкету. Повторная отправка использует один идентификатор. Ошибки заполнения, конфликт и нехватка места не должны выдавать ложный успех. Персональные данные не включаются в публичный каталог и технические журналы.

Загрузка медиа остаётся доступна на телефоне. Флешки, файловый менеджер Android и Bluetooth-передача не входят в посетительский сценарий.

## Переход на официальный домен

Адрес домена необходимо получить письменно: произнесённое в разговоре имя не используется как проверенная настройка.

- `KIOSK_SERVER_ORIGIN` — адрес API/сайта, доступный самому киоску; в производственном профиле HTTPS.
- `PUBLIC_APP_ORIGIN` — публичный HTTPS-origin, доступный телефону посетителя через мобильный интернет. Задаётся серверу и Android; сервер может сформировать полную ссылку продолжения.
- `VITE_APPLY_URL` — публичный полный адрес формы для веб-сборки, например `https://<проверенный-домен>/u/apply`.
- `CORS_ORIGINS` — явный список разрешённых origin при раздельных доменах. При обычной схеме «сайт и API на одном origin» CORS для запросов сайта не требуется. Значение `*` не использовать.

Изменения `VITE_...` и Android build defaults применяются при пересборке. Это не горячее перечитывание `.env` уже установленным приложением. Для адресов киоска предусмотрены защищённые настройки внутри APK. Нельзя перенаправлять неподтверждённые заявки на новый сервер: сначала завершить очередь на прежнем сервере или выполнить отдельно согласованный перенос.

Переход выполняется после настройки DNS, действительного TLS-сертификата и межсетевого экрана администраторами. Внешний HTTPS-вход проксирует необходимые web/API пути; MongoDB и внутренний backend-порт наружу не публикуются. Изолированная Wi-Fi-сеть/VPN киоска не должна предоставлять доступ ко всей корпоративной сети.

Проверить публичную QR-ссылку с телефона с выключенным университетским Wi-Fi. Получение доступа самим киоском ещё не подтверждает доступность формы посетителю. Просроченная или использованная ссылка не должна раскрывать анкету.

## Проверки перед эксплуатацией

- Версия Android — 12 или выше; актуальность Android System WebView проверяется отдельно, версия Android её не гарантирует.
- Назначение Device Owner и Lock Task подтверждены на устройстве. Полноэкранное изображение само по себе не означает блокировку выхода.
- Назначен пароль администратора, проверены ограничение попыток и восстановление доступа. Пароль не размещать в публичном интерфейсе.
- Проверены Home, Recents, системные панели, перезагрузка, сбой WebView, исчезновение сети и возврат в приложение после обслужиявания.
- Проверены возврат кабеля, перезапуск с накопленной очередью и восстановление повреждённой копии каталога.
- Отладочную сборку не считать производственной: перед постоянной установкой нужна подписанная release-сборка с отключённой отладкой. Сохранить ключ подписи для дальнейших обновлений; смена ключа потребует переустановки и может уничтожить локальную очередь.
- После установки APK и проверки восстановления отключить USB/Wi-Fi-отладку на устройстве; аппаратные сервисные порты должны оставаться под контролем сотрудников.

## Возврат к прежней версии

Сначала проверить и синхронизировать очередь заявок. Не удалять приложение и не очищать его данные, пока есть неподтверждённые анкеты. Удаление APK, сброс Android и потеря ключа шифрования уничтожают локальную очередь. Очистка медиа-кэша не должна затрагивать заявки.

Откат сервера выполняется из заранее сохранённых кода и резервной копии по процедуре администратора. При сохранении MongoDB новые дополнительные поля совместимы со старыми клиентами, но старый сервер не предоставляет APK новые маршруты синхронизации. Поэтому версии сервера и APK нужно согласовывать.
